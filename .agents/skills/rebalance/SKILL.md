# Rebalance (스마트 포트폴리오 리밸런싱 스킬)

이 스킬은 AI가 직접 계좌 데이터를 추론하여 최적의 매수/매도 수량을 산출하고, 실전 매매의 시간차(지연 체결, 미국장 LOC 2단계 분할 매매 등)를 완벽히 지원하는 엔드투엔드 워크플로우를 제공합니다.

---

## 🧭 전체 실행 워크플로우

```text
[시작] ➔ Step 0: Git Pull 및 대기 주문(pending_rebalance.json) 확인
   ├─ [대기 주문 있음] ➔ Branch A: 대기 주문 체결 처리 (전량 체결 / 부분 체결 / 2단계 매수 진행 / 취소)
   └─ [대기 주문 없음] ➔ Branch B: 신규 리밸런싱 가이드 생성 (시세 갱신 ➔ 계좌/모드 선택 ➔ 가이드 생성 ➔ Git Push)
```

---

## 🛠️ 상세 단계별 실행 지침

### Step 0: 최신 데이터 동기화 및 대기 주문 확인
1. 터미널에서 `git pull`을 실행하여 최신 변경사항과 대기 주문 상태를 동기화합니다.
2. `src/data/pending_rebalance.json` 파일의 존재 여부를 확인합니다:
   - **파일이 있는 경우:** ➔ **[Branch A: 대기 주문 체결 처리]**로 이동
   - **파일이 없는 경우:** ➔ **[Branch B: 신규 리밸런싱 가이드 생성]**로 이동

---

### [Branch A] 대기 주문 체결 처리

`src/data/pending_rebalance.json`을 읽고 현재 대기 중인 계좌 목록과 상태(`step`, `account`, 주문 목록)를 사용자에게 브리핑합니다.
*(단일 계좌 포맷 및 다중 계좌 포맷 `{ "계좌명": {...} }`을 모두 지원합니다.)*

#### 1. 대기 상태 확인 및 질문
대기 중인 계좌가 여러 개인 경우, 처리할 대상(예: "전체 일괄 체결", "특정 계좌만 체결", "다른 계좌 추가 리밸런싱 진행")을 먼저 선택하거나 지정할 수 있습니다.
`ask_question` 도구를 사용하여 다음 선택지를 제시합니다:
- **(Recommended) 가이드대로 전량 체결 완료** (모든 주문이 추천 수량대로 체결됨)
- **일부만 체결됨 (부분 체결)** (특정 종목만 체결되었거나 수량이 다름)
- **다른 계좌 추가 리밸런싱 진행** (기존 대기 주문을 유지한 채 새로운 계좌 가이드 생성)
- **대기 주문 취소** (특정 계좌 또는 전체 대기 주문 취소)

#### 2. 사용자 선택에 따른 분기 처리
- **Case 1: 전량 체결 완료**
  - **해외투자 계좌이고 `step === "WAITING_SELL_FILL"`인 경우 (2단계 매수 전환):**
    1. `src/data/portfolio.csv`에 매도된 주수를 먼저 차감 반영합니다.
    2. 확보된 매도 대금을 바탕으로 오늘 밤 실행할 **2단계 LOC 매수 가이드**를 출력합니다.
    3. `pending_rebalance.json`의 해당 계좌 `step`을 `"WAITING_BUY_FILL"`로 변경하고 매수 주문 목록을 저장한 뒤 `git add` ➔ `git commit` ➔ `git push`를 수행합니다.
  - **그 외 일반 체결 또는 최종 매수 체결인 경우:**
    1. `src/data/portfolio.csv`의 해당 종목 `수량`을 추천 가감 수량에 맞춰 자동 갱신합니다. (매도: 기존 수량 - 매도주수, 매수: 기존 수량 + 매수주수)
    2. 체결된 계좌를 `pending_rebalance.json`에서 제거합니다. (모든 계좌 처리가 완료되면 파일 삭제)
    3. ➔ **[Step 4: 데이터 영구화 & 완료]**로 이동합니다.

- **Case 2: 부분 체결**
  - 사용자에게 "체결된 종목과 실제 체결 수량을 알려주세요 (예: S&P 10주 매도, AI 3주 매수)"라고 안내합니다.
  - 사용자가 입력한 수량만 `portfolio.csv`에 반영하고, 미체결 잔여분은 대기 파일에 유지하거나 정리합니다.
  - ➔ **[Step 4: 데이터 영구화 & 완료]**로 이동합니다.

- **Case 3: 다른 계좌 추가 리밸런싱 진행**
  - 기존 대기 상태를 그대로 유지한 채 ➔ **[Branch B: 신규 리밸런싱 가이드 생성]**으로 이동합니다.
  - 신규 가이드 생성 후 기존 대기 주문과 함께 `pending_rebalance.json`에 병합 저장합니다.

- **Case 4: 대기 주문 취소**
  - 선택한 계좌를 `pending_rebalance.json`에서 삭제합니다 (남은 대기 주문이 없으면 파일 삭제).
  - `git add -A` ➔ `git commit -m "chore(rebalance): cancel pending rebalance order for {계좌명}"` ➔ `git push`
  - 사용자에게 "대기 중인 리밸런싱 주문이 취소되었습니다."라고 안내하고 종료합니다.

---

### [Branch B] 신규 리밸런싱 가이드 생성

#### 1. 최신 시세 갱신 및 계좌 진단
1. `run_command`로 `python scripts/update_prices.py`를 실행하여 실시간 주가/환율을 최신화합니다.
2. `src/data/portfolio.csv`를 읽어 `자산구분`이 `보유종목_`으로 시작하는 계좌들의 현재 비중과 목표 비중을 비교합니다.
3. 목표 비중 대비 괴리율(±3%p 이상 등)이 큰 계좌를 분석하여 사용자에게 현황을 간략히 브리핑합니다.

#### 2. 대상 계좌 및 리밸런싱 모드 선택
`ask_question` 도구를 사용하여 계좌와 모드를 선택받습니다:
- **계좌 선택:** `ISA`, `ISA_정은`, `연금저축`, `연금저축_정은`, `해외투자`, `해외투자_정은`, `IRP_회사`, `IRP_개인`
- **모드 선택:**
  1. **순수 리밸런싱 (매도 + 매수):** 기존 보유 자산 내에서 비중 초과 종목 매도 후 부족 종목 매수
  2. **추가 납입 리밸런싱 (매수 전용):** 신규 투입할 예수금(현금 금액)을 입력받아 부족 종목만 매수

#### 3. AI 리밸런싱 추론 규칙 (Reasoning Guidelines)
에이전트는 다음 규칙에 따라 직접 최적의 매매 주수를 계산합니다:
- **순수 리밸런싱:**
  - $\text{계좌 총평가금} = \sum \text{종목별 현재 평가금}$
  - $\text{종목별 목표금액} = \text{총평가금} \times (\text{목표비중} / 100)$
  - $\text{조정 필요금액} = \text{목표금액} - \text{현재평가금}$
  - 매도 종목: 조정 필요금액이 음수인 종목 $\rightarrow \lfloor |\text{조정필요금액}| / \text{현재가} \rfloor$ 주 매도
  - 매수 종목: 조정 필요금액이 양수인 종목 $\rightarrow \lfloor \text{조정필요금액} / \text{현재가} \rfloor$ 주 매수 (매도 대금 한도 내 배분)
- **추가 납입 리밸런싱:**
  - $\text{목표 총액} = \text{현재 총평가금} + \text{추가투입금}$
  - 목표 비중 대비 현재 비중이 가장 부족한 종목부터 투입금을 우선 배분하되, **총 매수 예정 금액이 추가투입금을 초과하지 않도록** 보수적으로 계산합니다.
- **수량 단위:** 국내 ETF는 **정수(1주 단위 내림)**, 해외 주식은 기본 정수(필요시 소수점 지원).

#### 4. 계좌 유형별 주문 가이드 출력

##### 🇰🇷 A. 국내 계좌 (ISA, 연금저축, IRP)
매도 대금 확보를 위해 **매도를 상단 1단계로, 매수를 하단 2단계로 명확히 분리**하여 출력합니다:

```markdown
### 📋 [{계좌명} 리밸런싱 주문 가이드]
⚠️ **반드시 1단계(매도)를 먼저 체결**시킨 후 예수금을 확인하고 2단계(매수)를 진행해 주세요.

---
#### 🔴 1단계 : 매도 주문 (먼저 실행하여 예수금 확보)
1. **{종목명}** | **{수량}주 매도** (현재가 {가격}원 / 약 {금액}원 확보)

---
#### 🟢 2단계 : 매수 주문 (1단계 체결 확인 후 실행)
1. **{종목명}** | **{수량}주 매수** (현재가 {가격}원 / 약 {금액}원 소요)

---
💬 *증권사 앱에서 주문 후 바로 체결되면 `"체결 완료"`라고 말씀해 주세요. (지정가 대기 시 나중에 다시 스킬을 불러주셔도 됩니다!)*
```

##### 🇺🇸 B. 해외 계좌 (`해외투자`, `해외투자_정은`)
해외 계좌는 기본 **`LOC (종가 지정가)`** 방식을 적용하며, 순수 리밸런싱인 경우 **Day 1 매도 ➔ Day 2 매수**의 분할 프로세스로 안내합니다:

* **순수 리밸런싱 (Day 1 매도 우선):**
```markdown
### 📋 [{계좌명} 리밸런싱 가이드 - 1단계: LOC 매도]
미국장 LOC 주문은 종가 체결 특성상 매도 대금이 체결 전까지 입금되지 않으므로, **오늘 밤에는 매도를 먼저 진행**합니다.

---
#### 🔴 [오늘 밤 실행] LOC 매도 주문
1. **{티커/종목명}**
   • 주문 유형: **LOC 매도**
   • 수량: **{수량}주**
   • 추천 LOC 가격: **${현재가}** (확실한 체결을 원할 경우 ${현재가 * 0.995:.2f} 권장)
   • 예상 회수액: 약 ${달러금액} (약 {원화금액}원)

---
📌 *내일 밤 매수 예정 종목 (참고용): {매수예정 종목 및 대략적 주수}*

🌙 *내일 아침 출근길에 증권사 앱에서 매도 체결을 확인하신 후 `"매도 체결 완료"`라고 말씀해 주시면, 확보된 예수금 기준의 2단계 LOC 매수 가이드를 바로 발행해 드립니다.*
```

* **추가 납입 리밸런싱 (즉시 매수 가능):**
  - 매도가 없으므로 즉시 **LOC 매수 가이드**를 출력합니다.

#### 5. 대기 주문 파일 저장 및 Git Push
가이드 출력이 완료되면 즉시 `src/data/pending_rebalance.json`을 작성(기존 파일이 있으면 병합)하고 Git에 Push합니다:
1. `src/data/pending_rebalance.json` 파일 생성 / 병합:
   ```json
   {
     "계좌명": {
       "account": "계좌명",
       "mode": "pure | additional",
       "step": "WAITING_FILL | WAITING_SELL_FILL | WAITING_BUY_FILL",
       "createdAt": "YYYY-MM-DDTHH:mm:ss",
       "sellOrders": [...],
       "buyOrders": [...]
     }
   }
   ```
2. Git 커밋 및 푸시 실행:
   - `git add src/data/pending_rebalance.json`
   - `git commit -m "chore(rebalance): save pending rebalance order for {계좌명}"`
   - `git push`

---

### [Step 4] 데이터 영구화 & 완료 자동화

체결이 완료되어 최종 수량이 확정되면 다음 절차를 수행합니다:

1. **CSV 수량 갱신:**
   - `src/data/portfolio.csv` 파일에서 해당 계좌의 종목 행을 찾아 `수량` 컬럼 값을 새로운 보유 수량으로 수정합니다.
2. **대기 파일 정리:**
   - `src/data/pending_rebalance.json` 파일에서 체결된 계좌 항목을 제거합니다. (모든 대기 계좌가 완료되면 파일 삭제)
3. **시세 및 평가금액 자동 재계산:**
   - `run_command`로 `python scripts/update_prices.py`를 실행합니다.
4. **Git 자동 커밋 & 푸시:**
   - `git add src/data/portfolio.csv src/data/pending_rebalance.json .agents/skills/rebalance/SKILL.md`
   - `git commit -m "feat(rebalance): complete rebalancing for {계좌명}"`
   - `git push`
5. **최종 보고:**
   - 사용자에게 리밸런싱 전/후 주수 변화와 새로 계산된 비중을 깔끔한 표로 요약 브리핑하며 완료합니다.
